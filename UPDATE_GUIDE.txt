WADHWANI REGISTRATION — PWA INSTALL + 10-MINUTE ALARM V10
==========================================================

MAIN V10 FEATURES
-----------------
1. INSTALLATION REQUIRED BEFORE USING THE PORTAL
   - The website is now an installable Progressive Web App (PWA).
   - When opened in a normal Chrome/Edge/other browser tab, the main login/registration portal is blocked by an Install Wadhwani Registration screen.
   - Chromium browsers use the browser's native PWA installation prompt when available.
   - iPhone/iPad and browsers without the programmatic prompt show manual Add to Home Screen / Install app instructions.
   - There is no Continue Without Installing button.
   - After installation, the user must launch Wadhwani from the Home Screen/app launcher. The portal becomes available in standalone installed-app mode.
   - The existing Messenger/Facebook in-app browser notice remains first. Users must open the link in a real browser before installation.

2. NEW 10-MINUTE SCHEDULE ALARM
   - While a registered student is signed in, the app watches the selected date/time locally.
   - When the current time reaches 10 minutes before the scheduled slot, a Schedule Reminder modal appears.
   - It uses the same soft two-tone flight-attendant-style chime and polite spoken message.
   - The reminder repeats until the student presses “Okay, I’m preparing”.
   - If the student signs in with fewer than 10 minutes remaining, the reminder appears immediately with the approximate minutes remaining.
   - The reminder stops once the scheduled time begins, the student acknowledges it, or the student becomes Ongoing/Completed/No Show.

3. FACILITATOR CALL / REMIND ALARM PRESERVED
   - Call/Remind still creates the polite flight-attendant-style alarm.
   - The call alarm takes priority over the 10-minute schedule reminder.
   - It continues until the student selects On the way, Can’t attend, or Reschedule.
   - If system-notification permission is granted, the app also asks the service worker to show a device notification.

4. LIVE STUDENT STATUS CHECKING
   - The existing lightweight check of only the logged-in student's record remains.
   - The check continues to be requested while the installed app is in the background when the browser permits background execution.
   - Called, Ongoing, Completed, and No Show changes still switch the student's visible state without a full browser reload.

5. COMPLETED PAGE — UNINSTALL INSTRUCTIONS
   - Completed students still see only the thank-you page after login.
   - The page now displays device-appropriate instructions for removing Wadhwani.
   - Android: press/hold app icon → Uninstall or App info → Uninstall.
   - iPhone/iPad: press/hold app icon → Remove App → Delete App / Remove from Home Screen.
   - Desktop: use the installed app/browser menu and choose Uninstall/Remove app.
   - Wadhwani does not attempt to uninstall itself because the operating system controls app removal.

CODE.GS
-------
- No new Apps Script backend logic is required specifically for the V10 PWA/install/10-minute local alarm feature.
- The included Code.gs is the same backend supplied with the user's current V9 code and preserves duplicate-name checking, appointment settings, status actions, and registrations.
- You do NOT need to redeploy Apps Script only for the V10 frontend/PWA files if your current V9 Code.gs is already deployed correctly.

IMPORTANT BROWSER LIMITATION
----------------------------
A PWA/service worker cannot guarantee an exact alarm if the browser/app process is fully terminated. This V10 version provides:
- repeating sound/vibration modal while the app session is active;
- background status/schedule checks when the browser allows timers to run;
- service-worker system notifications once the active/background app detects the reminder or facilitator call.

For a guaranteed server-triggered notification when the PWA is completely closed, a separate Web Push/FCM backend and push-subscription registration would be required. The V10 service worker already contains a generic push event handler so that a future push backend can be added without redesigning the notification UI.

NOTIFICATION PERMISSION
-----------------------
When the student chooses Enable Alerts in the app, the browser may ask permission to show notifications. The user/browser controls this permission and the website cannot bypass a denial.

HOSTING REQUIREMENTS
--------------------
- Use HTTPS hosting (Netlify HTTPS is suitable). Service workers and installable PWAs require a secure context, except localhost development.
- Keep all files in the same site/root structure shown above.
- The service worker is registered from ./sw.js and controls the same scope.

TEST CHECKLIST
--------------
1. Open the hosted URL in Chrome as a normal browser tab.
2. Confirm that Login is blocked by the Install Wadhwani Registration screen.
3. Install the app using the Install button or browser menu.
4. Launch Wadhwani from the Home Screen/app launcher.
5. Confirm that the Login page becomes available in standalone mode.
6. Log in as a student and choose Enable Alerts; approve notification permission when offered.
7. Use a test schedule whose start time is about 10 minutes away.
8. Confirm the Schedule Reminder modal, chime, voice, vibration, and acknowledgement button.
9. From Facilitator, use Call/Remind and confirm the call alarm replaces/takes priority over the schedule reminder.
10. Change the student to Ongoing and confirm the Ongoing page appears without a full browser reload.
11. Change the student to Completed and confirm the Thank You page plus uninstall instructions.
12. Close/reopen the installed app. Because browser identity is intentionally not persisted, it should still begin at Login.
