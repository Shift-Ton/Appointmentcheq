WADHWANI REGISTRATION — V16 CONSOLE / DEPLOYMENT FIX
===================================================

V16 FIXES
---------
1. Service worker no longer intercepts normal page/asset GET requests.
   - Fixes the sw.js Failed to fetch / FetchEvent network-error console problem.
   - The service worker remains available only for browser notifications / Firebase push.
   - Frontend registers sw.js?v=16 with updateViaCache: none so an old worker is replaced faster.

2. Added favicon.svg and explicit favicon links.
   - Prevents browsers from falling back to https://<owner>.github.io/favicon.ico and producing the reported 404.

3. Registration identity compatibility.
   - Preferred endpoint remains checkRegistrationIdentity (the lightweight V14+ endpoint).
   - If the currently deployed Apps Script still returns “Unknown API action”, V16 temporarily falls back to resolveLoginId + checkStudentEligibility so duplicate ID/full-name protection continues to work.
   - You should still deploy the included Code.gs so the lightweight endpoint is available.

CAUSE OF “Unknown API action”
-----------------------------
The frontend and Apps Script Web App are separate deployments. Uploading index.html/script.js to GitHub Pages does NOT update the Apps Script /exec backend. The error means the /exec URL in script.js is serving an older Apps Script deployment that does not yet contain the checkRegistrationIdentity route.

REQUIRED BACKEND UPDATE
-----------------------
1. Open the Google Apps Script project used by APPS_SCRIPT_WEB_APP_URL.
2. Replace Code.gs with the Code.gs in this V16 package.
3. Save.
4. Deploy > Manage deployments. Edit the Web app deployment and choose New version (or create a new Web app deployment).
5. If Google gives you a different /exec URL, paste that exact URL into APPS_SCRIPT_WEB_APP_URL at the top of script.js.
6. Upload the V16 frontend files to GitHub Pages.
7. Reload the page. If an old service worker still controls one tab, close all Appointmentcheq tabs and reopen the URL once.

PREVIOUS V15 NOTES

WADHWANI REGISTRATION — PREMIUM TICKET FLIP V15
==========================================================

STUDENT FLOW
------------
1. First browser visit shows LOGIN, not the registration form.
2. Existing Student ID -> opens the existing ticket and remembers the Student ID on that browser.
3. Unknown Student ID -> popup says “This user has not registered yet” and offers Continue to Registration.
4. The Login page also has Register New Student for first-time registrants.
5. After successful registration, the browser remembers that Student ID and future opens restore the latest ticket automatically.
6. The student Logout icon is removed from the ticket view to prevent accidental identity switching / repeated login. Facilitator logout remains available.

DUPLICATE PREVENTION
--------------------
• Student ID is checked on the registration form when the ID field loses focus and again before Choose Schedule.
• Full name (First + Middle + Last) is checked when the name fields lose focus and again before Choose Schedule.
• Existing Student ID -> registration is blocked and user is directed to Login.
• Existing normalized full name -> registration is blocked and user is directed to Login using the Student ID used for that registration.
• registerStudent() still repeats the duplicate ID and duplicate full-name protection under the write lock.

PREMIUM TICKET
--------------
• Rebuilt as a premium CARES digital access pass.
• Large queue number, premium dark-green gradient, security watermark, ticket perforation, protected QR panel, schedule grid, status and live-sync area.
• Ticket status remains Upcoming / Ongoing / Complete / Expired.
• Expired tickets still offer Select new available seat.

DATE-LOCKED QR
--------------
• QR is generated but deliberately blurred/covered so it is unscannable before the appointment date.
• The QR unlocks only when the current server date matches the student's registered appointment date.
• It locks again outside that date.
• The lock uses the server-synchronized clock used by the ticket system.

LIGHTWEIGHT STATUS
------------------
• Ticket status still uses the compact getStudentNotificationState endpoint.
• No batch list is fetched for routine ticket polling.
• Polling pauses while the tab is hidden and resumes when the student returns.

BACKEND CHANGE — REQUIRED
-------------------------
V15 adds the checkRegistrationIdentity API route, so replace Code.gs and deploy a NEW Apps Script Web App version.
No new Google Sheet columns are required and setupSystem() does not need to be rerun solely for this V15 change if V11+ setup is already complete.

DEPLOYMENT
----------
1. Replace Code.gs with V15 Code.gs.
2. Deploy a NEW Web App version.
3. If the /exec URL changes, paste the new URL into APPS_SCRIPT_WEB_APP_URL in script.js.
4. Upload/replace: index.html, script.js, style.css, sw.js, firebase-config.js and _headers.
5. Existing registrations are preserved.

IMPORTANT ABOUT REMEMBERED STUDENT
----------------------------------
• The browser stores only the remembered Student ID key.
• The ticket data itself is always fetched again from Google Sheets.
• Clearing site data, using another browser/device, or private/incognito mode can require Login again.


COMPLETED TICKET FLIP V15
-------------------------
• When the lightweight ticket status changes to completed, the premium ticket flips to its reverse side.
• The reverse side shows a polite thank-you message, the student name, queue number, original schedule, and completion time when available.
• Student live polling stops after completion, exactly as before.
• A remembered registered student who reopens the browser link is restored through getStudentNotificationState(); if the server returns completed, the completed reverse-side ticket opens automatically.
• No new Sheet columns or Apps Script routes are required for this V15 visual/flow update.
